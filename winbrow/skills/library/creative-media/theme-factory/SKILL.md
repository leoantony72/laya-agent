# Theme Factory

## When to Use

Use when GOAL asks for a consistent look across a deck, document, report, or
HTML page, or asks to pick a theme.

## When NOT to Use

- Do not use to copy a company's trademarked brand without permission.
- Do not use for a one-off image; use `canvas-design`.
- Do not apply a theme that fails contrast or accessibility.
- Do not claim a DOCX/PPTX theme was applied if only colors were changed.

## Prerequisites

- Read `references/themes.md` once with `read_document`.
- Apply the tokens through the relevant skill: `pptx`, `docx`, `canvas-design`,
  or an HTML file written with `create_text_file`.

## Step Pattern

1. Ask what the artifact is and who the audience is if that is unclear.
2. Offer 2–3 themes from the reference by name, with a one-line mood summary.
3. After the user chooses, extract the palette and font pairing.
4. Apply consistently:
   - one accent color for emphasis, not five
   - body text at accessible contrast
   - headings in the display font, body in the sans/serif pairing
   - the same spacing scale throughout
5. For slides/docs, pass the colors and fonts to the relevant generator. For
   HTML, write CSS variables:
   `:root { --bg: ...; --ink: ...; --accent: ...; --muted: ...; }`.
6. Verify contrast: normal text should be at least 4.5:1; large text 3:1.
7. Report the theme name and the tokens used.

## Output Shape

A theme name plus a token block (colors, fonts, spacing) and the artifact. If
the artifact is generated by another skill, pass the tokens in that skill's
spec.

## Recovery

- User dislikes all options: ask for a reference image or three adjectives.
- Contrast fails: darken text or lighten the background; do not ignore it.
- Artifact cannot accept fonts: apply colors only and say so.
- User asks for a brand: require the official palette and fonts.
